# 成步堂桌宠玩法优化需求与路线图

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 更新日期 | 2026-07-17 |
| 适用平台 | macOS、Windows 10/11 x64 |
| 文档目的 | 统一记录玩法目标、优先级、验收口径、暂缓范围与后续建议 |
| 当前发布版本 | Windows `v1.0.0`；macOS `integration/desktop-pet` |

## 1. 结论摘要

目前玩法已经从“点击角色看动作”扩展为三个相互衔接的循环：

1. 日常陪伴：随机动作、拖动、甩飞、环境反应和陪伴节奏。
2. 收集发现：首次解锁提示、法庭记录和重复触发次数。
3. 主动挑战：六件证物归档、有序归档和轻量交叉询问。

下一阶段不建议继续无序增加小游戏。应优先提高已有玩法的可发现性、内容容量、完成反馈和跨平台稳定性，再决定是否开发心理锁等新系统。

## 2. 优先级定义

### P0：核心体验或发布阻断

满足下列任一条件即为 P0：

- 用户无法理解桌宠能做什么。
- 高频操作重复、失效、抢焦点或破坏桌面工作。
- 奖励丢失、重复触发或覆盖正在展示的台词。
- macOS 或 Windows 主流程无法正常运行。

P0 应优先修复，不应等待新玩法排期。

### P1：显著提高留存和完整度

P1 不阻断运行，但能够明显提升复玩意愿、目标感或内容消耗速度。通常应在一个小版本内完成。

### P2：探索性增量

P2 是值得验证但尚未证明价值的新玩法。应先做独立原型，不应直接侵入角色拖动、甩飞或全局输入链。

### HOLD：条件不足，暂缓

HOLD 不是永久拒绝。只有满足文档列出的前置条件后，才能重新进入审批。

## 3. 全局玩法原则

所有新玩法和优化必须遵守以下原则：

1. 单次体验控制在 5～20 秒，用户可以随时离开。
2. 自动行为只能提供陪伴感，不能自动展开小游戏或遮挡工作内容。
3. 专注和安静模式禁止自动演出，但用户主动点击、拖动和启动玩法仍然可用。
4. 失败只结束附加挑战，不能清空已有进度、隐藏惩罚或删除已出现的道具。
5. 已经获得的奖励可以因交互暂停，但不能永久丢失。
6. 主台词、临时消息、玩法结果、奖励和首次解锁提示必须按优先级排队，不能互相覆盖。
7. 不读取剪贴板、键盘、其他应用文本或网络内容；不新增非必要系统权限。
8. 不增加签到、连续天数、每日任务、体力、排行榜或付费式数值系统。
9. macOS 与 Windows 可以使用不同实现技术，但核心规则、奖励与文案含义应保持一致。

## 4. 已实现需求

### GP-001 首次解锁提示

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 状态 | macOS、Windows 已实现 |
| 用户价值 | 让用户知道一次操作已经产生了新的法庭记录 |

需求规则：

- 仅在记录从未解锁变为已解锁时触发。
- 重复触发只增加次数，不重复制造“首次解锁”事件。
- 动作、拖动、菜单、临时消息或玩法结果展示期间暂停提示。
- 回到真正空闲状态后恢复提示，不能因为用户点击而永久丢失。
- 提示不接收鼠标，不抢焦点，不创建新的可激活窗口。

验收标准：

- 同一记录连续触发 100 次，只产生一次首次解锁提示。
- 提示展示中开始拖动，提示立即隐藏；回到空闲后重新出现。
- 多条提示按解锁顺序展示，旧计时器不能跳过新提示。

### GP-002 智能随机动作袋

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 状态 | macOS、Windows 已实现 |
| 用户价值 | 降低连续重复动作造成的机械感 |

需求规则：

- 单击随机和右键“随机动作”共用互动动作袋。
- 自动待机使用独立动作袋，不能消耗用户互动动作顺序。
- 一轮内覆盖所有候选动作后再开始下一轮。
- 两轮交界不能连续出现相同动作。
- 候选动作动态变化时必须安全重建当前轮次。

### GP-003 六件证物完整归档

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 状态 | macOS、Windows 已实现 |
| 用户价值 | 为散落动画增加明确目标和完成奖励 |

用户路径：

1. 用户主动触发六件证物散落。
2. 用户在桌面寻找并点击证物。
3. 每次回收显示 `已归档 x/6`。
4. 六种不同证物全部回收后，播放完整证据链奖励。

验收标准：

- 只有六种不同证物全部回收才奖励。
- 重复回调、旧轮次、预览、缺少素材、取消和自然淡出均不得误奖励。
- 完成奖励必须等待最后一件证物台词结束。
- 用户在等待期间进行其他操作，只能暂停奖励，不能清除奖励。

### GP-004 陪伴节奏与安静模式

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 状态 | macOS、Windows 已实现 |
| 用户价值 | 让桌宠适应工作、演示和休息等不同场景 |

档位定义：

| 档位 | 自动行为 | 用户主动操作 |
|---|---|---|
| 专注 | 禁止 | 允许 |
| 轻陪伴 | 低频 | 允许 |
| 活跃 | 较高频 | 允许 |
| 安静 30 分钟 | 临时禁止 | 允许 |

要求：

- 默认使用轻陪伴。
- 档位和安静截止时间持久化。
- 安静到期后恢复此前档位。
- 系统时钟回拨后必须重新计算并安排到期任务。
- 任何时刻只能存在一个自动行为计时器和一个安静到期计时器。

### GP-005 轻量交叉询问

| 属性 | 内容 |
|---|---|
| 优先级 | P0 |
| 状态 | macOS、Windows 已实现 |
| 用户价值 | 提供最具逆转裁判辨识度的主动短玩法 |

入口：

- 右键菜单“开始交叉询问”。
- 低频待机后出现的“追问案情”入口；必须由用户点击后才展开。

用户路径：

1. 每轮显示一组恰好三句的证言。
2. 用户使用“上一句”和“下一句”查看证言。
3. 用户对认为矛盾的证言点击“异议”。
4. 选错时显示轻提示并允许继续。
5. 选对后播放“异议 → 决定性证据 → 结论”的收尾。

规则：

- 每轮控制在 10～20 秒，当前超时为 15 秒。
- 错选不扣分、不终止、不写成功记录。
- 正确结果只能结算一次。
- 关闭、右键、拖动、打开法庭记录、启动新玩法或超时都必须安全退出。
- 旧回调和旧 token 不能影响新回合。
- 不要求键盘输入、自由文本、麦克风、AI 或网络。

当前内容：

- 已有 8 道本地人工题目。
- 每题恰好三句，矛盾位置覆盖第 1、2、3 句。
- 题目袋一轮内不重复，跨轮不连续重复同题。

### GP-006 有序证物归档

| 属性 | 内容 |
|---|---|
| 优先级 | P1 |
| 状态 | macOS、Windows 已实现 |
| 用户价值 | 将普通回收升级为可重复的桌面寻找挑战 |

用户路径：

1. 真实六件证物散落时生成一组完整随机顺序。
2. 底部顺序条持续显示六件顺序和当前进度。
3. 用户按照提示依次寻找并点击证物。
4. 完全按序时，将普通奖励升级为“完美归档”奖励。

失败规则：

- 点错后仅本轮有序挑战失败。
- 被点错的证物仍按普通流程回收。
- 其余证物继续存在，用户仍可获得普通六件完整归档奖励。
- 不允许失误后清空道具、重置普通进度或隐藏惩罚。

奖励仲裁：

- 普通六件回收成功：播放普通完整证据链奖励。
- 六件完全按序成功：只播放升级奖励。
- 同一轮禁止连续播放普通和升级两个奖励。

## 5. 建议开发需求

### GP-007 法庭记录完成度与分类进度

| 属性 | 内容 |
|---|---|
| 优先级 | P1 |
| 建议工作量 | S～M |
| 推荐顺序 | 下一批第一项 |

目标：让法庭记录从“看过的列表”变成清晰的长期完成目标。

建议需求：

- 在法庭记录顶部显示总进度，例如 `已发现 12/18`。
- 按经典动作、彩蛋、桌面互动、环境反应、庭审挑战分组显示进度。
- 锁定项继续显示模糊提示，但不能直接泄露完整触发方法。
- 分类全部完成时提供一次性轻量完成提示，不增加货币或等级。
- 保留每项触发次数和首次发现时间。

验收标准：

- 新增或删除目录项后，分母自动更新。
- 迁移旧数据不丢失解锁时间和次数。
- 完成提示只触发一次，且遵守奖励和台词优先级。

建议：该需求比增加新小游戏更能放大现有内容价值，应优先开发。

### GP-008 情境化新手提示

| 属性 | 内容 |
|---|---|
| 优先级 | P1 |
| 建议工作量 | S |
| 推荐顺序 | 与 GP-007 同批 |

目标：提高隐藏玩法的自然发现率，不加入强制教程。

建议提示节点：

- 首次启动：单击、双击、拖动、右键。
- 多次单击但从未右键：提示右键还有更多玩法。
- 已经拖动但从未触发甩飞：提示快速拖动后松手会产生不同结果。
- 已经散落证物但未完成回收：提示桌面上的证物可以逐一点击。
- 已解锁普通归档但未完成有序归档：强调底部顺序条代表推荐次序。
- 从未进入交叉询问：在合适的思考动作后提供一次追问热点。

限制：

- 每类提示最多出现 1～2 次。
- 用户处于专注或安静模式时，不自动展示教学提示。
- 提示不能与首次解锁、奖励或玩法结果同时出现。
- 不增加“下一步”强制流程，不阻止用户关闭或拖动桌宠。

### GP-009 交叉询问内容扩充

| 属性 | 内容 |
|---|---|
| 优先级 | P1 |
| 建议工作量 | M |
| 推荐顺序 | GP-007/008 之后 |

目标：降低 8 道题目被快速记住后的重复感。

建议需求：

- 将题库扩充至 12～16 题。
- 继续保持每题三句、一个明确矛盾和一句短结论。
- 题目应覆盖时间、光线、路线、数量、物品状态和前后自相矛盾等类型。
- 每句建议不超过 24 个中文字符，结论建议不超过两行。
- 新题必须由人工编写和审阅，不接入网络或生成式 AI 在线出题。
- 题目袋继续保证一轮内不重复和跨轮不连续重复。

内容审查清单：

- 是否存在“可能有手机、手电、备用出口”等未排除前提。
- 矛盾是否只依赖三句证言本身，不要求外部知识。
- 正确结论是否能在一次阅读后理解。
- 错误两句是否确实可以同时成立。

### GP-010 玩法状态与退出一致性

| 属性 | 内容 |
|---|---|
| 优先级 | P1，持续性 |
| 建议工作量 | 每批必测 |

每个玩法必须覆盖下列统一出口：

- 左键点击角色。
- 从角色有效区域开始拖动。
- 点击透明区域。
- 右键打开菜单。
- 打开法庭记录。
- 启动另一玩法。
- 超时。
- 应用退出。

每个出口都必须同时完成：

1. 取消当前计时器和延迟回调。
2. 隐藏玩法专用按钮、HUD 和临时窗口。
3. 让旧 session/token 失效。
4. 恢复空闲动作和台词。
5. 恢复待处理奖励与首次解锁提示。
6. 继续服从当前陪伴档位。

建议：为这些公共出口维护一份跨玩法回归矩阵，但暂时不要抽象大型协调框架。

## 6. 暂缓需求

### GP-011 心理锁玩法原型

| 属性 | 内容 |
|---|---|
| 优先级 | P2 / HOLD |
| 当前结论 | 不进入正式研发 |

暂缓原因：

- 围绕角色画圈会与桌宠搬动、抓取和甩飞使用同一拖拽输入。
- 全窗口透明手势层会扩大点击拦截区域，影响桌面工作。
- 纯手势完成方式缺少无障碍替代操作。
- 需要锁链、碎裂、遮罩和输入仲裁等新资产与基础设施。
- 如果只缩减成依次点击几把锁，重复价值不足以支撑独立玩法。

重新审批的前置条件：

1. 交叉询问已经证明用户愿意主动进入短小游戏。
2. 已有清晰的锁链视觉原型。
3. 锁的交互区域与角色抓取区域完全分离。
4. 提供非拖拽、可由无障碍执行的替代方案。
5. 不使用全局鼠标监听或新增系统权限。
6. 至少准备三种不同解除规则，而不是重复同一画圈动作。

### GP-012 通用小游戏协调层

| 属性 | 内容 |
|---|---|
| 优先级 | HOLD |
| 当前结论 | 不提前抽象 |

暂缓原因：目前只有交叉询问和有序归档两个成熟小游戏，直接引入通用协调器容易产生过度设计。

重新评估条件：

- 第三个小游戏通过产品审批并进入开发。
- 三个玩法出现至少三项完全相同的 session、取消或奖励仲裁逻辑。
- `PetView` 或 Windows renderer 的状态分支已经难以通过局部模型隔离。

## 7. 明确不做的范围

以下内容不进入当前路线图：

- “今日一案”、每日签到、连续登录和限时任务。
- 积分、货币、体力、等级、排行榜和付费养成。
- 自动读取微信或其他应用聊天内容。
- 剪贴板、全局键盘、全局快捷键和前台应用监控。
- 麦克风、语音识别和摄像头玩法。
- 在线 AI 自动生成题目或长篇剧情。
- 强制多轮庭审、长文本分支或通用剧情编辑器。
- 因错答、错序或超时扣除已有收集进度。

## 8. 跨平台一致性要求

| 能力 | macOS | Windows | 一致性要求 |
|---|---|---|---|
| 单击/双击动作 | 已实现 | 已实现 | 动作语义一致 |
| 拖动/甩飞 | 已实现 | 已实现 | 速度影响结果，落地可恢复 |
| 首次解锁提示 | 已实现 | 已实现 | 只触发一次，可暂停恢复 |
| 法庭记录 | 已实现 | 已实现 | 核心条目与计数语义一致 |
| 六件证物 | 已实现 | 已实现 | 六种唯一证物和完成奖励一致 |
| 有序归档 | 已实现 | 已实现 | 错序降级、成功升级奖励一致 |
| 交叉询问 | 已实现 | 已实现 | 三句证言、15 秒、错选可继续 |
| 陪伴节奏 | 已实现 | 已实现 | 专注/轻陪伴/活跃/安静语义一致 |
| 聊天名字监听 | 部分场景可用 | 不提供 | 不作为核心玩法或发布门禁 |
| 背景感知 | macOS 可选 | 不提供 | 不影响核心玩法完整度 |

## 9. 建议排期

### 阶段 A：质量与可发现性

建议优先级：最高。

- 完成 GP-007 法庭记录完成度。
- 完成 GP-008 情境化新手提示。
- 补充真实 Windows 10/11 鼠标交互验收。
- 为菜单、拖动、透明区域、超时和玩法切换维护回归清单。

建议目标：先让更多用户发现并完成现有内容。

### 阶段 B：内容容量

- 完成 GP-009，将交叉询问题库扩充至 12～16 题。
- 对现有题目进行前提完整性和两行布局复审。
- 为有序归档增加更明显的“下一件”视觉提示，但不改变失败规则。

建议目标：提高重复游玩的变化感，而不是增加数值系统。

## 10. 发布验收清单

每次新增或修改玩法，至少验证：

- [ ] 用户能从界面或情境提示发现入口。
- [ ] 单局能够在 20 秒内退出或完成。
- [ ] 专注和安静模式不会自动展开玩法。
- [ ] 右键、拖动、透明区域、面板、新玩法和超时均能退出。
- [ ] 旧 session、token 和延迟回调不会污染新一局。
- [ ] 错答或错序没有隐藏惩罚。
- [ ] 奖励只结算一次，且不会覆盖最后一句台词。
- [ ] 首次解锁提示可以暂停并恢复。
- [ ] 新控件不抢焦点，并具备可理解的无障碍标签。
- [ ] 不新增剪贴板、全局输入、网络或系统权限。
- [ ] macOS arm64/x86_64 编译通过。
- [ ] Windows 模型测试、Electron smoke test 和 NSIS 构建通过。
